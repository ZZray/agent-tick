# 屏幕跑马灯通知

作者：Ray Zhang。2026-11-19。

## 行为
托盘“显示与通知”里的“屏幕跑马灯”开关（设置名 `marquee`，默认关）。开启后，提醒卡（`toast_windows.go`）同时转给 `marquee_windows.go`：
在悬浮窗所在屏幕工作区上方 8% 处开一个 1000×140 CSS px 的全透明置顶窗口（`view=marquee`），播一条光带 + 滚动文字，播完藏起，空闲 2 分钟销毁。
右下角卡片、托盘闪烁、提示音不变。“勾了一项”（`item`）不上屏幕，宿主在 `marquee()` 里过滤。

## 透明与点穿的取舍（实测，Win11 26300）
- 透明靠“WebView 默认背景色环境变量 + `DwmExtendFrameIntoClientArea(-1)` + 无系统背景”，与毛玻璃是否开启无关（`newClearWebView`）。
- **不能加 `WS_EX_LAYERED`**：加了以后 WebView2 画不出透明，整块窗口变白（无论是否保留 DWM 扩展）。而没有分层，`WS_EX_TRANSPARENT` 不会让鼠标穿透到别的进程的窗口。
- 所以无法点穿，窗口接收鼠标，交互由页面处理：鼠标停在光带上时只停住“停留”倒计时（不消失、光效不停）；退场途中移上来则取消退场；点一下收起并打开对应会话（`tickMarqueeOpen` → `openSession`，与右下角卡片一致）。
- 曾先做成“鼠标一移上去就让开”和“悬停时所有动画暂停”，都被否决：用户要的是悬停不消失、动画不停、点击看具体通知。
- 残留缺口：窗口（1000×96 CSS px）在显示期间会挡住下面的点击。

## 页面坑
`renderNow()` 对不认识的 `view` 会画完整面板，新增 `view` 必须在 `renderNow` 里提前返回（本次先漏了，窗口里出现了面板骨架）。

## 验证边界
Go：设置默认关、落盘、写失败回滚；开关关闭或 `item` 不进队列。Node：队列上限 4、逐条播放、悬停只停倒计时不暂停动画、点击打开会话并清队列（`web/marquee.test.cjs`）。
真机：隔离实例（独立端口与数据目录）下，真实屏幕截图确认透明光带、光尘，悬停 5 秒以上不消失且光尘仍在变化，点击后收起。未覆盖：多显示器混合 DPI、全屏应用上方、开机自启后的首次创建。
