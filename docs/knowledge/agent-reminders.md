# Agent 请求时的遗漏条目提醒

版本：0.5.21。作者：Ray Zhang。

## 触发与边界

用户希望 Agent 再次请求 Tick 时，能知道自己可能忘记更新某个条目，减少用户回到原会话追问的次数。提醒随当前请求返回，只看该请求明确关联的会话，不扫描其他任务，不创建后台轮询或用户通知。

运行会话的 doing 条目至少 30 分钟未更新时提示核对；成功收尾但仍有未结束条目时提示遗留情况。提示包含稳定 ID、序号和状态，最多列三条及剩余数量，不把未知执行情况直接判定成卡死。相同问题在 30 分钟内不重复；节流放在 Store 的独立内存状态中，不通过正常 change 写回，避免制造新的进度时间、事件或自动归档活动。

Item.updatedAt 表示该条最后一次有效上报。修改本条字段或明确再次报告 doing 可刷新；重发同一计划、改其他条目或改会话标题不会掩盖旧条目。旧条目回退到 startedAt，两者都没有则不声称超时。waiting、blocked、paused 和结束状态不按正常运行超时提醒。

提醒要求 Agent 对照执行器、日志或其他真实证据确认：仍执行、等待依赖、已经结束或已取消。服务不自动修改条目，不补 done，不拦截既有 finish。提示后的修正仍由 Agent 通过正常 API 完成；明确失败或取消任务不要求补成成功。

## 接入

MCP 把提示追加到成功工具调用结果。CLI 请求自动带 Agent 标记并显示提示。HTTP Agent 显式发送 `X-Tick-Agent-Request: 1`，读取并 URL 解码 `X-Tick-Reminder` 响应头；普通 UI 和 JSON 响应契约保持原状。持久化只保存条目更新时间，提醒节流在服务重启后重新开始。

## 验证

新增提醒的 9 项定向回归与独立审查通过；最终 Go 回归 80 个顶层测试、38 个子用例，共 118 run，vet 通过。覆盖 MCP 成功响应、HTTP 显式启用且 JSON 不变、CLI 接线、30 分钟边界与节流、单项更新时间、旧时间回退、两条 doing 暂停后只确认一条、219 条时的响应长度，以及收尾提醒无状态副作用。

复审发现并修正三个接线问题：会话恢复会刷新所有 doing 的 StartedAt，提醒必须优先用单项 UpdatedAt；已结束会话改名不能被当成本次收尾；HTTP start 复用旧会话时的附加响应结构也要返回提醒头。未为通过提醒检查而改变旧计时或 finish 契约。

以上为受控 Store/HTTP/MCP 回归；没有向其他真实会话注入超时条目，也不能保证 Agent 一定采纳提醒。实际执行仍需 Agent 自行核实，Skill 已同步该处理要求。
