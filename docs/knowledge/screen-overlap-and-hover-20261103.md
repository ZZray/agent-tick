# 画布堆叠、连线与侧栏反馈

作者：Ray Zhang。日期：2026-11-03。基线：main@104df84，正式运行 0.5.27。

## 现场与根因

用户截图中，竖向树的“本轮安排”模块和真实子 Agent 卡片相互覆盖，点击整理后仍觉得堆叠；另反馈连线流动太多、侧栏没有开合过渡、节点缺少悬浮反馈。截图文件为 codex-clipboard-d2f7e96f-e8c5-4d24-8984-226e720c9ce4.png 和 codex-clipboard-e1af540d-5502-4c1f-a38c-777f5e261f09.png。

纯 cvArrangeLayout 会按子树包围尺寸分配位置，横竖轴互换本身没有发现错误。读取现场最新拓扑后，在独立浏览器中的初次布局及整理均无重叠；这不能证明用户截图里的旧状态没有问题，也不能把截图直接归因于整理算法。

独立 VM 确认：已有 CV.pos 的模块重新进入画布，但 CV.sizes 没有该 ID 时，cvLayout 不将它视为需要检查的节点，旧位置可以与真实子 Agent 重叠。ResizeObserver 又只更新连线和小地图，不复核异步变高后的碰撞。因此即使整理过，后续节点重现或尺寸变化仍可能再次堆叠。

## 修复边界

- 缺少尺寸记录的重现节点也参与碰撞检查；无冲突的手动位置不变，只避让实际碰撞的子树。
- ResizeObserver 在尺寸真实变化时合并到下一帧，复用局部布局检查。更新尺寸快照使检查收敛；整理动画期间用 CV.pos 的目标位置，避免拿动画中间位置误判。
- 保留原树布局算法。整理按实际卡片尺寸分配，实时内容更新不写回旧位置。

## 连线与反馈

新增画布偏好 edgeFlow，缺省开启；更多菜单提供“连线流动”开关，关闭会停止并隐藏动态 path，静态连接仍显示。stroke-dasharray 从 9/91 调为 2.5/97.5，周期由 2.4 秒调为 6 秒。它按路径长度占比缩短，不是固定像素长度；节点边框流光独立。

侧栏用 clip-path 播放 180ms 的开合，不逐帧改变画布占位宽度；浮层与固定栏展开宽度统一为 15.5em。关闭期间保留 railClosing，让实时刷新不会提前移除展开结构。反向操作读取当前裁切再接续；同方向请求直接复用，防止键盘 Tab 反复重播。减少动态会取消动画并直接落到最终状态。

节点悬浮边框使用自身状态色，模块卡和标题提示可拖动、点击查看详情；根任务提示点击标题展开步骤。复用现有自绘 tooltip，不新增任务状态或业务操作。
