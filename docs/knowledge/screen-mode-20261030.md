## 问题与证据

- 大屏复用了悬浮窗的顶层任务列表，却没有渲染父卡中的子任务，导致运行中的子 agent 遗漏。回归用“父任务已结束超过 30 分钟、子任务仍运行”验证：旧代码遗漏子任务，修后显示子任务卡和父任务标题。
- 页数、当前页和自动翻屏使用了不同的宽度口径。可见宽度 1000、内容宽度 1250、偏移 250 时，旧代码已到最右仍亮第一个页点。修后按列布局的内容宽度及列间距生成同一组落点，页点和翻页共用。
- 隔离浏览器中，长步骤把卡片撑到约 1143–1202px，高于当时 847px 的画布。普通步骤改为两行摘要，当前步骤三行，同一数据下卡片约 341–399px。
- 大屏窗口创建期间的关闭请求原来只检查窗口句柄，初始化完成后仍可能显示。现在保存目标开关状态，在显示及重建前检查最新请求。源码及独立复审支持该判断；后续隔离原生快速开关验收通过，覆盖范围见下文。

## WebView2 的退出约束

当前依赖 `github.com/jchv/go-webview2` 的版本为 `v0.0.0-20260205173254-56598839c808`。它的 `Destroy()` 仅投递 `WM_CLOSE`，不是同步销毁。窗口过程随后销毁窗口并投递 `WM_QUIT`，由 `Run()` 消费。

如果窗口初始化完成后取消显示，也需要在同一线程上调用 `Destroy()`、再调用 `Run()` 泵完退出消息。直接销毁后复用线程，旧 `WM_QUIT` 可能中断下一次 WebView2 初始化。已显示窗口的 `Run()` 退出时已经消费该消息，无需再运行一次。维护时应回源核对依赖版本，不把这个约束泛化到其他 WebView 实现。
