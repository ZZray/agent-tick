# 整组归档与残留任务

版本：0.5.21，基于 0.5.20。作者：Ray Zhang。

## 显示与归档的归属

0.5.20 把已结束父任务和未结束子任务混在不同窗口的筛选规则里：悬浮窗在父任务结束 30 分钟后隐藏整组，大屏保留灰色父上下文，并把长期无更新的子任务写成“仍在执行”。灰色父卡没有操作按钮，大屏单项归档父任务又会让未归档子任务单独出现。

修订后，两种窗口都区分活跃/等待子任务和仅剩长期无更新子任务的组。前者保留必要父上下文，后者收进待清理入口，提供明确的整组归档。普通面板、大屏和悬浮窗共用 `POST /api/sessions/:id/archive`，请求 `{"archived":true}` 归档该会话和所有后代；`false` 明确恢复整组。原有单项 PATCH 契约不变。

整组操作在 Store 锁内完成，保留状态、清单和最后进度时间。响应包含会话快照和本次实际改变的 `changedIds`，撤销只还原本次改变的记录，不恢复原先已归档的后代。归档产生 `sessions` 批量 SSE 事件，前端逐条 ingest 后只调度一次刷新；自动归档整轮也只推送一条批量事件，避免超过订阅缓冲时逐条事件丢失。

## 自动归档

桌面设置 `AutoArchive` 默认 false，托盘和面板通过既有设置所有者读写。开启后，每分钟检查一次，不运行单独后台服务。

- 只自动处理已结束的逻辑根会话；父不存在或已归档时，恢复后的子任务可成为逻辑根。仍在运行的根任务不自动归档。
- 全组已结束时，距最近结束、进度和可查询的对话活动至少 30 分钟。
- 存在未收尾子任务时，父已结束，整组最近活动至少 60 分钟。
- 任意等待、受阻、明确待续（paused）或近期对话活动都会保留该组。结束时间缺失时保留，避免把未知时间当作已经过期。

对话文件活动在 Store 锁外查询，包含已结束父子会话；归档前再在锁内依据当前状态和进度时间判断，避免用旧快照覆盖新进展。查不到活动只代表未知，不能据此宣布进程已停止。归档仅改变可见性，原 running 状态不会被改成 done 或 cancelled；Agent 继续汇报时复用已有 unarchive 契约恢复对应会话。

## Agent 流程模块

技能、Kiro 常驻规则/Hook、MCP 全局说明和 items 参数提示统一要求：多个流程或职责使用 `# 模块名`、`# 父流程 / 子流程`；按实际工作单元分组，通常一至三层足够，简单短任务可不分组，不为每条步骤创建模块。doing/done 随执行更新，只有真实并行步骤同时 doing。主任务收尾前核对本次已经返回的子 Agent 也已 finish，取消项说明原因。

模块卡仍来自原清单，不增加 Store 会话，不创建额外会话来迎合画布。更新技能可改善后续任务的登记；不能保证已经运行的 Agent 自动重新加载旧上下文。

## 验证

整组归档、条件保护和恢复已通过 Go 回归。冻结页面 EE3F5732 的真实 Chrome 受控验证覆盖错误反馈、即时撤销、预先归档子任务保持原状，以及 81 条批量 SSE 同步，两窗口一致。

最初浏览器验收发现归档后 `S.undo` 赋值晚于刷新调度，撤销按钮未及时显示，现已补发调度并复验。后续脚本把后台页面的透明退场节点计为仍可见、在无宿主绑定的页面验证贴边条，分别纠正了可见性判定和宿主桩；失败收据保留。真实触屏、多屏跨 DPI、热插拔和长期运行性能未覆盖。
