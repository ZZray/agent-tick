# 大屏顶栏与任务导航改版

日期：2026-11-03，基于 0.5.25。作者：Ray Zhang。范围：`web/index.html` 的 `renderScreen`、`cvRailTask`、`.scr-h` 和 `.cv-rail` 样式，以及 `web/screen.test.cjs`。

## 用户反馈

用户在 1920 宽的大屏截图上圈出顶栏和左侧导航，说"设计得不好"，并授权布局、展示形态和交互都可以改。真实数据基线截图（5 个主任务、11 张卡、画布 150%）里看得到这些问题：

- 顶栏文字只有 11px，统计行是一排灰字，看不出主次；当前任务标题和画布上的卡片标题重复，长标题把状态挤到边上。
- 顶栏是实色底，卡片平移到上方时被一条硬边切断。
- 导航只有 96px 宽，任务名两行 11px 就被截断；完成度 100% 但在等用户的任务显示橙色环，界面上没有任何说明。
- 导航框从顶部一直撑到底部，任务少时下面是一大段空列。

## 改法

顶栏只放全局状态：品牌、KPI 和右侧的结束入口、时钟。KPI 用 24px 数字配 12px 标签，依次是在跑、子 agent、等你（橙色可点，沿用 `data-cv="wait"` 的依次跳转）、等依赖、今天勾了和总进度。总进度带一条 3px 进度条和百分比。没有任务在等用户时，显示"没有要你处理的"，前面带一个绿点。顶栏底部有 14px 渐隐，卡片滑到下面时会淡出，不再被硬边切断。

导航展开后宽 248px，每行显示：

- 进度环 38px，中间写百分比；
- 两行标题，完整标题和当前步骤放在 `title` 提示里；
- 状态文字和 `done/total`；
- 当前步骤，只显示一行。

状态文字和环用同一个颜色：进行中用品牌色；等你和子任务等你用橙色，并显示等待时长（复用 `data-clock="waitnow"`）；等依赖也用橙色；失败用红色；待续、可能掉线和已结束但子任务未收尾用灰色。在等用户的行加一层浅橙底。选中行用左侧 3px 品牌色竖条加 `--active` 底标出。导航高度跟着内容走，最高到视口底部，超出后在列表内滚动。

导航可以收起成 68px 的环形栏，偏好存在 `tick.canvas.railCompact`。窗口不超过 960px（`CV_RAIL_FORCE`）时强制收起，并隐藏标题行和切换按钮。收起时，当前任务标题回到顶栏。收起或展开时如果开着跟随，会重新适应当前流程，因为可用视口变了。

`[` 和 `]` 按导航顺序循环切换主任务，镜头瞬时到位，与 `0` / `F` 一样不带动画。导航顺序没有改，等你的任务也不会被挪到最前，以免点击目标跳位。

HUD 的左边界原先硬编码为 126px（96px 导航加 30px），现在改为 `rail.offsetWidth + 30`。可用视口仍是 `rail.offsetWidth + 20`。

## 放弃的方案

- 等你的任务置顶排序：状态一变，行就跟着移动，挂墙看时容易点错。
- 窄于 1100px 时自动收起：1280 宽下 248px 导航仍留出 1000px 以上的画布，没有必要。
- 给"等你"做持续脉冲：属于无限循环抢注意，已有顶部橙色光和卡片橙色描边。

## 自动跟随、右下角开关与自绘提示

### 用户反馈

用户要求自动跟随能跟到当前通知、当前正在执行和正在更新的节点，并在右下角放一个开关。用户还指出原生 tooltip 不好看，要换成自绘提示，并希望整体改善无限画布的聚焦、流畅度和体验。截图里跟随图标没有处于按下状态。

### 原因

旧版有两处问题，用户看到的“跟随失效”就是这两处造成的：

- 平移、缩放、拖卡、小地图、详情滚动都会调用 `stopFollow`。它会把 `CV.follow` 永久设成 false 并存盘，之后不会自动恢复，所以用户手动看过一次画布，跟随就一直关着。
- 跟随开着时，也只在所选主任务的拓扑变化时移动镜头。同一结构下的进度更新、其他主任务的更新和新出现的等你，都不会让镜头移动。这条限制是 0.5.22 的设计（“非选中任务更新不抢视角”），现在用户明确要求改掉。

### 现在的规则

开关有三种状态，对应文案和行为如下：

| 状态 | 开关文案 | 进入条件 | 恢复或退出 |
|---|---|---|---|
| 跟随中 | 跟随中 | 默认状态 | 点开关关闭 |
| 暂停 | 已暂停 Ns | 手动平移、缩放、拖卡、操作小地图、点导航或按 `[` `]` | 15 秒（`CV_FOLLOW_IDLE`）没有操作就自动接着跟；按 F、点“回到当前流程”或点开关立刻恢复 |
| 暂停 | 看详情中 | 打开详情 | 关闭详情后开始 15 秒计时 |
| 暂停 | 概览中 | 打开全局概览 | 点开关回到跟随 |
| 关闭 | 跟随已关 | 点开关 | 点开关重新开启；关闭状态存在 `tick.canvas.follow` |

`cvFollowing()` 只判断开关、详情和暂停计时，不判断概览，因为概览里仍要保留归档后的自动整理。`cvFollowGo` 自己会跳过概览。

跟随目标按 `cvFollowGo` 的顺序选：

1. 还没看过的新“等你”，按 `waitSince` 取最新一个。“看过”记在 `CV.seenWaits`，键是“会话 ID + 开始等待时间”。点顶栏“项等你”也算看过。
2. 刚有进度更新的会话。“更新”指会话状态或任一条目状态的签名有变化；只改标题、问题措辞或耗时不算。在当前主任务里，更新一到就跟过去；换到另一个主任务时，当前目标要先停够 8 秒（`CV_FOLLOW_DWELL`），没到时间的先排进 `CV.followQueued`，由每秒的定时器补跳。这样几个 agent 同时报进度时，镜头不会来回跳。
3. 都没有时，留在当前执行路径上。

镜头对准会话当前 doing 所在的模块节点，没有模块时对准会话卡片。换主任务时，导航的选中项会立刻重画。第一轮浏览器验收发现导航没有重画，`cvFollowGo` 已在换主任务时调用 `schedule()`。

### 流畅度

- 镜头过渡的时长按屏幕上的移动距离计算：近处 320ms，跨任务的远跳最长 760ms。时长通过 `cvApply(anim, ms)` 写到 `transitionDuration`，拖动或滚轮可以从当前帧接管。
- 更新的节点会出现一圈 2px 品牌色描边，1.1 秒内向外散开消失。同一节点 3 秒内只描一次；跟随到达的目标在镜头停下后再描。减少动态时不播放。
- 键盘操作（`[` `]`、`0`/`F`）保持瞬时，不加动画。

### 自绘提示

大屏从 `cvModuleCard` 到 `renderScreen` 的所有 `title`，以及 HUD 和小地图开关的提示，都改成了 `data-tip`。提示复用全局的 `ui-tip`（悬停 450ms 出现，下方放不下就翻到上方，支持换行）。大屏里提示层的 `z-index` 设为 200，高于导航和 HUD。`sessionRow` 原本就用 `data-tip`。

### 测试契约变化

三条旧测试断言了“其他主任务更新、同结构进度更新不动镜头”，这正是用户要求改掉的行为，已经改写：

- 关掉跟随后，原来的“不动镜头”断言仍然成立；
- 只改标题时不动镜头；
- 条目状态变化会让镜头跟过去；
- 只改问题措辞不触发重新对焦。

新增一条用例，覆盖等你优先、同任务立即跟随、跨任务 8 秒停留与排队、暂停后恢复到最新活动，以及开关的三种状态。

### 验证

- Node 117/117，内联脚本 `node --check`，go vet 和 go test 都通过。HTML SHA256 前缀为 `77B71174`。
- 用无头 Chrome 打开 headless 候选：真实数据副本，端口 17781，用 `PATCH /api/sessions/{id}/items/{ref}` 模拟进度。观察结果：
  - 打开后跳到正在等你的任务；
  - 另一个主任务更新后，8 秒内不跳，到时间后跳过去，导航选中项同步变化；
  - 同一任务里的模块更新时，描边动画在播放；
  - 按 `-` 后开关显示“已暂停 15s”并逐秒倒数；
  - 自绘提示出现在开关上方；
  - 点开关能恢复，再点能关闭并写入 localStorage；
  - 大屏里 `[title]` 数量为 0，控制台没有错误。
- 截图在本机 `%TEMP%\tick-screen-shots\follow-*.png`。

### 未验证

- 描边动画只通过 `getAnimations()` 确认在播放，截图没有抓到动画中间的画面。
- 触屏、跨 DPI 和英文截图。

## 0.5.26：悬浮侧栏、右上时间与模块当前步骤

作者：Ray Zhang。日期：2026-11-03。以下约定取代上文侧栏宽度、时钟位置和结束入口的旧方案。

收起侧栏保留进度圆环。鼠标进入或键盘聚焦时，侧栏内部浮层展开；离开后收起。浮层不改外壳占位、画布矩形、相机或节点位置，也不写入展开偏好。桌面按钮用于固定展开或收起；宽度不超过 960px 时保持窄列，按钮改为临时展开入口，触屏无需依赖 hover。Esc 优先关闭临时侧栏，再沿用大屏原有退出行为。鼠标点击收起后，不因按钮获得普通焦点立即重开；键盘 focus-visible 可以展开。

高频悬浮切换不做宽度动画，只沿用 100ms 的按钮颜色反馈。完成 scr-side、scr-main/header/cv-stage 的倒 L 结构接线；原草稿只有样式与相机坐标变换，renderScreen 尚未输出对应容器。CV.view 继续用窗口坐标，写入世界层时减 stage 原点，避免平移、滚轮和小地图各用一套坐标。

时间与日期始终位于右上角，包括无任务状态。大屏移除“已结束”入口和历史面板，普通面板历史及存储数据保持。当前模块之外的历史和未来步骤仍按原规则折叠。

父模块的当前摘要从 allItems 查找后代 doing，不再只查直接 items；纯父模块因此也能显示正在执行的具体步骤。摘要以小点和次要小字号显示，最多两行，不加“当前步骤”标签、底色或竖条高亮。待执行项仍标为“下一步”，不冒充正在执行。模块分母仍从原清单派生，不额外登记汇总条目。

Agent 说明同步到 Skill、Kiro 常驻规则及提示、MCP、CLI 和 HTTP 协议：大模块是阶段或职责，子模块是工作对象，步骤写清对象、动作和可检查结果；先列已知范围、未来项保持 todo，切换模块前核对旧 doing。复测默认保留原模块与稳定 ID，阶段和证据写 note/evidence；仅实际计划调整时移组。规则说明不构成对其他 Agent 遵循率的保证。
