# 大屏改成无限画布

日期：2026-11-02。目标：`feat/detach-screen-20261102` 合并 `origin/main`（0.5.15）之后的工作区。

## 为什么改

用户看过多列流式布局的大屏后否决了它：实际任务不会很多，大屏应当是悬浮窗同款的卡片，每个会话一张，可以自由拖动，要有无限画布的平移和缩放。旧版的自动翻屏还有一个具体缺陷：翻到后面时，排在最前面的"等你"卡会离开视野。

## 做法

- 卡片直接复用 `sessionRow(s, live)`。`.s` 系列样式不依赖悬浮窗容器，外面包一层 `.cv-card` 提供底色、边框和阴影。快捷按钮、底部的"接力提示 / 详情"和清单行悬停的复制、跳过在大屏窗口里没有宿主绑定或容易误触，用 CSS 隐藏；清单的勾选按钮不接收指针（`it-tick`），拖动仍可从它上面起手，挂着看时手滑不会改任务状态。
- 展开状态沿用悬浮窗：默认全部收成一行（`S.open` 为空），点会话头展开。第一版为了让大屏信息更全，首次见到会话就自动展开，用户看到后说"没有沿用悬浮窗方案，展开太长"，已去掉。按下的卡片自动置顶，展开时不会被下面的邻卡压住；卡片是绝对定位，展开不会把邻卡推开。
- 展开后的长清单沿用悬浮窗的折叠：只留当前这一步前一条、后四条，前后各折成一行（"前面 N 项已完成"、"后面还有 N 项"），点一下展开全部。折叠在 `itemsHtml` 里按 `FLOAT` 判断，`FLOAT` 只包含 `view=float/mini`，第一版大屏（`view=screen`）没算进去，展开后整份清单全显示，用户看到 60 多项的清单后指出。现在写成 `FLOAT || SCREEN`，面板详情仍然显示全部。复用组件时要核对里面所有按视图判断的分支。
- 世界坐标原点在左上角，`.cv-world` 整体做 `translate + scale`，点阵背景画在世界里的 `::before` 上，所以平移、缩放和程序跳转的过渡三者同步。不用 `will-change`，缩放后文字保持清晰。
- 手势：按在卡片上拖动超过 4px 是移动这张卡，没超过当点击（卡片照常展开、收起）；按在空白处或中键拖动是平移；滚轮按光标位置缩放（`exp(-deltaY * 0.0015)`，范围 25% 到 250%）；双击空白、`0`、顶栏"适应"收进视野（缩放不超过 150%）。拖动结束后 40ms 内吞掉紧随其后的 click。
- 位置和视图存 `localStorage` 的 `tick.canvas`（大屏窗口和悬浮窗同源）。新会话的卡片先隐藏，渲染后量实际高度，按"先靠上再靠左"找不压着别的卡的位置，列数最多按窗口宽度换算（2 到 5 列）。
- 等你的卡不在视野里、且 30 秒内没人操作画布时，视图平滑带过去；顶栏"N 等你"点击依次跳到它们。

## 验证（2026-11-02，隔离实例，端口 17359）

候选程序 `0.5.16`，18 个演示会话（17 张卡，子 agent 在父卡里）。通过 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9335` 用 CDP 驱动真实 WebView2 页面：

- 卡片拖动：`wait0` 从 `(404,0)` 到 `(1095,777)`，屏幕位移除以缩放 0.405 与位移一致；拖动后展开状态不变，z-index 抬高。
- 滚轮 `deltaY=-500`：41% 变 86%，与 `exp(0.75)` 一致。空白处拖动平移 (+200,-140)，`0` 键回到适应视图。
- 清掉 `tick.canvas` 后重载，卡片按 3 列自动落位，控制台没有错误。
- 前端测试 40 项、`go vet`、`go test` 通过。

未验证：扩展屏拔插、其他 DPI、触屏和触控板手势（触控板双指滚动目前会缩放，不是平移）、长期运行、同一画布上 50 张以上卡片的性能。
