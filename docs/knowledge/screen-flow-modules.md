# 大屏的分层模块与执行连线

目标版本：0.5.20，基于 0.5.19。作者：Ray Zhang。

## 模块来自清单

大屏的模块卡由现有条目 `group` 投影而来，不创建 Store 会话，也不改会话、条目 ID 或后台接口。单层模块仍按原方式登记；使用 ` / ` 分隔时形成层级，例如：

```text
# 后端 / 接口 / 鉴权
实现令牌检查
验证错误令牌
# 后端 / 数据
保存用户设置
# 验证
执行回归
```

模块窗口跟随实际当前条目：优先显示 doing 所在路径，支持并行分支；没有 doing 时再取受阻或下一待办。主图只投影当前分支与必要祖先，已经完成或无关的历史、未来流程折成数量入口，在有界列表里查看，不重新变成画布节点。全未开始的 planning 任务不展开模块；全部步骤完成但会话尚未收尾时只保留主任务卡。

前后数量按真实条目顺序计算。“前面”不等于全部已完成，里面仍有待办或受阻时保留真实状态。当前模块清单和主任务清单都以当前步骤附近为默认窗口，手动查看全部时也限制滚动高度，避免一张长卡撑坏布局。

模块是只读视图，不携带真实会话的后台操作入口。顶栏的任务数仍统计真实会话，不把模块当成新增 Agent。

## 位置与连线

模块位置按所属会话和路径记忆。整理只读当前投影，根会话统一从左侧开始，每条任务树占一条纵向通道，子 agent 和子流程向右延伸。可见拓扑、等待问题区和紧凑父上下文变化，以及显式展开、收起、主动归档成功后，合并自动整理；普通同结构的文字与进度更新保留位置。拖动、平移和缩放期间延后处理。旧版巨树布局首次升级时自动收紧，同一结构下重新打开仍保留手动位置。

连接使用细曲线，不使用大箭头。真实会话正在运行，且分支中有执行中的条目时，连线才显示轻微流动；等待、暂停或完成时停下来。减少动态模式使用静态线。任务刷新更新现有 SVG 路径的几何与状态，避免反复重建节点打断动画。

模块首次出现采用短距离淡入，不对已经存在的卡片重复播放入场。现有整理动画的状态保留机制继续生效。

## 新内容与两种窗口的同步

用户反馈新会话需要点“整理”才出现。双页隔离浏览器测试确认，新卡已收到并生成，但放大后的标题完全在视野外。状态更新在测试中于 129ms 内进入大屏和悬浮窗，未复现持续丢失同步。

0.5.20 的新卡进入、完成退出与流程结构变化会先合并整理，再调整相机；普通同结构的进度刷新保留位置。正在拖动、平移或连续缩放时，操作结束约 1.2 秒再处理。等待卡和普通新卡共用这条规则，不再另走旧的 30 秒等待规则。

大屏默认显示活跃、等待和规划中的真实会话，主任务与执行中的子 Agent 分开计数。结束会话移出主画布；结束父会话仍有活跃子 Agent 时，只保留紧凑父上下文，不投影其历史模块。顶栏提示入口可查看最近的结束结果，用户悬停或键盘聚焦后主动归档；失败时保留条目并显示错误，不自动删除历史数据。

悬浮窗把子 Agent 放在父任务下，且会隐藏已分离到独立窗口的任务；这属于两种视图的显示范围，不是重新创建任务或改变后台状态。

## 窗口归属

大屏窗口在隐藏状态下设置 `WS_EX_TOOLWINDOW`，再按原有流程应用全屏位置并显示。大屏不占任务栏图标，托盘仍提供入口，Esc 仍可退出。其他窗口样式不在本次修改范围。

## 0.5.19 基础验证

隔离 Chrome 使用合成 HTTP/SSE 数据执行 23 项检查，覆盖按执行显现、深层祖先、未来模块隐藏、位置保存、拖动、整理中刷新、SVG 节点复用、减少动态、明暗主题和两种尺寸。双页测试的标题、当前步骤、等待与完成状态一致；新根任务和模块无需整理即可进入视野，手动交互期间视角不抢动。

DeepSeek 已审阅真实渲染的合成截图，静态底线按可读性意见调整为 1.1px、透明度 0.52，运行高亮保持轻量。它对兄弟流程关系的一项误读未采纳，不以模型判断替代实际数据关系。

隔离候选 0.5.19 的真实原生大屏已读取窗口样式：`EXSTYLE=0x80`，`WS_EX_TOOLWINDOW` 已设置，`WS_EX_APPWINDOW` 未设置。大屏打开与关闭 API 均执行完成，预览进程已结束。

原生检查须等产品完成全屏初始化：WebView 库会先显示一个默认窗口再完成 Embed，不能把第一个可见 HWND 当作已设置好样式的大屏。这里核验的是最终全屏状态，没有截图验收系统任务栏，也未执行 Esc 输入测试。第二台显示器的不同 DPI、触屏和长期性能未因此自动视为通过。

## 0.5.20 聚焦修订

用户在真实规模下否决了 0.5.19 的历史全展开策略：完成会话与执行过的全部模块都铺在画布上，整理后的整树过大，文字被缩得很小。此前少量合成任务的渲染通过不能代表大清单可读性。

本轮验收使用 80–100 步、多分组、大量完成记录的合成场景，并保留当前会话拓扑的匿名结构（最长清单 90、87、84、82 项）。匿名结构默认收为 10 卡、3 个模块，完成记录退出主图，根从同一左侧起点向右延伸。真实 Chrome 的主动归档及展开交互 23 项、大规模合成 21 项、匿名实际拓扑 9 项通过，覆盖前后折叠、列表滚动、SSE 推进、失败反馈与整理后无重叠。

最终增加等待问题区、紧凑父上下文的结构分类：卡片 ID 和关系不变也可能改变高度，不能仅用节点关系判断是否整理；同分类的标题、问题文案和耗时刷新仍保留位置。Node 70 项（其中大屏 38 项）、Go 75 项、vet、完整页面脚本语法、diff-check 和 Windows 候选构建通过，独立 Codex 复审覆盖最终差异。DeepSeek 已评审匿名聚焦截图。实际触屏、多屏跨 DPI、热插拔、长期性能和用户主观观感仍待验证。

最终页面结构增量在真实 Chrome 中 13/13 通过：running ↔ waiting 高度 120→204→120，整理后无重叠；手摆父卡结束后回到 x=0、缩为 65px 紧凑关系卡，活跃子任务保留。同分类标题和进度刷新未移动手摆位置。

## 0.5.20 灰色父卡与残留子任务（待修）

以下为 0.5.20 的调查记录；0.5.21 的修订与验证见[整组归档](archive-groups.md)。

2026-11-02 用户截图反馈灰色父卡无悬停操作，且同组在悬浮窗中消失。对照 `bec5826` 和本机 0.5.20 API：父 `s_46d588` 已在 14:49 结束，子 `s_7a82db` 仍为 running，最后更新 14:47，调查时已超过一小时；`/api/activity` 无该子任务的活动证据。后者只能支持“可能掉线”，不能证明进程已经结束。

源码确认三处显示和操作缺口：`cvCards` 把所有未结束子任务都计入保留父上下文的条件，包含 dormant；`cvCard` 因此仍写“子 agent 仍在执行”，且紧凑父模板没有操作按钮。`floatData` 的常规列表只投影顶层会话，结束父任务超过 30 分钟后退出 recent，未归档父仍使子任务被 `isChild` 排除，导致本组无入口；waiting 子任务还可能走独立提示卡，不能泛称所有子任务都会消失。大屏 CSS 还明确隐藏普通卡片的快捷操作。

“隐藏”不等于归档：Store 的 Archived 写入由显式 Patch 驱动，没有现成定时归档。大屏右上结束列表的 `cvArchive` 只归档点击的单个会话；普通面板 `archive` 则会连同直属子任务归档。只从大屏归档父任务会让未归档子任务成为独立根卡，不能解决整组残留。当前手动处理入口是面板中选中父任务并归档整组；新进度上报可按现有 Store 契约恢复对应会话。

建议修订范围：活跃、等待与可能掉线分开表达；结束父的残留子任务在两种窗口保留一致的可处理入口，提供清楚的整组归档动作。自动归档若增加，应区分全部结束与仅超时未更新，不把后者自动标成成功；等待/受阻与近期活动不能混作残留。具体启用条件与延迟尚未确定。本轮仅回源调查，未改产品代码，也未归档或结束这些会话。
