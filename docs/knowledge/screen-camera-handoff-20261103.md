# 大屏执行交接与跟随范围

作者：Ray Zhang。日期：2026-11-03。基线：0.5.26，main@c7351ae。

## 已复现的问题

用户报告大屏来回跳，问同一个父节点 A 下，从子节点 C 到 B 是否经过 A。当前代码没有规划中转路径；变化来自执行上报和画布投影。

独立 Codex 和主代理用 0.5.26 的真实函数复现：C doing → C done／B todo → B doing，镜头候选依次为 C、根会话、B。完成与开始分开到达时，中间没有 doing，cvLeafOf 回退到会话，拓扑变化又请求适应视图。60ms 合并不足以覆盖这段交接。

同根会话中的父汇总与子 Agent 更新还会互相抢焦点：原来的 8 秒停留仅限制跨根任务，同根内 0–1ms 的更新可以连续改候选。浏览器的 CSS 过渡并不能修正错误候选。另有运行时 transitionDuration 被下一次 morph 的 style 覆盖的问题；源码事实不直接证明原生画面回到起点。

## 调整约定

- 数据立即刷新，自动镜头单独合并。交接空窗保持已有视角，只追踪真实 doing 叶节点；父级汇总和未来 todo 不触发自动回父镜头。
- 默认跟随当前选中的根会话及其真实子 Agent。其他项目的进度和新问题不抢焦点。“更多”中的当前会话／全局选择写入画布偏好；旧偏好没有此值时采用当前会话。
- 手动适应、整理、导航与自动镜头分开。手动操作沿用原有暂停／恢复行为；全局模式保留跨任务停留和等待优先规则。
- 镜头连续更新沿用当前可见插值，刷新保留过渡时长。具体合并、停留与最长等待参数以最终验收记录为准。

## 计时诊断

首轮实现的新增回归在两轮修改后仍有一个计时断言失败，按本机流程停止重试。用户明确选择继续诊断和针对性修复后，独立只读审查定位：

1. 模块 C 完成后被投影隐藏，签名循环只看画布可见会话，漏记其 done。C 再次 doing 时仍与旧签名相同，执行事件丢失。测试的合并起点因此晚于真实执行变化。
2. autoDue 虽封顶，重排 timer 仍额外至少等待 240ms，持续更新可使实际移动一直后延。验收需要检查实际镜头移动，不能只检查截止字段。
3. 父汇总带 group 后成为模块节点，绕过了只检查原生父卡的过滤。交接用例同时覆盖有分组和无分组的父汇总。

## 执行节点边框流光

参考用户指定的 Ant Design BorderBeam 6.6.5 页面：https://ant-design.antgroup.com/components/border-beam-cn 。已实际查看基本演示、截图并读取计算样式：1px 遮罩边框、100px 渐变段、6 秒线性循环、offset-distance 沿边缘运行。截图在本轮本机证据目录的 border-beam-reference-ready.png；首张空白截图不作为参考证据。

复用现有 edgeBeam 的 data-fx 特效层与遮罩，增加连续模式，原通知的一次性模式保留。轨迹圆角取实际卡片圆角。只给真实执行叶节点播放，没有执行模块时可播放根卡；父汇总不重复亮。停止执行、离场、暂停、等待、页面／宿主隐藏和减少动态时取消并移除动画；普通刷新保留同一个特效层。已有流光的节点不再额外播放更新描边。
