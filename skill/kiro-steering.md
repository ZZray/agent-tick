# Tick 状态同步（强制）

用户看 Tick 小窗了解你在做什么。Tick 的状态必须随时和实际一致，按下面的时机立即同步，不攒到最后补。完整用法见 `tick` 技能（`~/.kiro/skills/tick/SKILL.md`）。

| 时机 | 必须做的事 |
|---|---|
| 开始 2 步以上的任务 | 先 `tick start` 写完整清单；本对话已有会话就 `tick add` 追加，不另开 |
| 清单包含多个流程或职责 | 必须用 `# 模块名` 或 `# 父流程 / 子流程` 分段；按实际工作单元划分，通常一至三层足够，简单短任务可不分组，不要每条步骤建一个模块 |
| 当前目标实质变化 | `tick_rename`（命令行 `tick rename`）更新为“稳定主题 · 当前目标”，标题简短；普通步骤和追问不改名，旧名保留供搜索 |
| 开始某一条 | 先标 `doing` |
| 做完某一条 | 马上标 `done`，note 写能核对的结果 |
| 卡住（环境、权限、失败） | `tick notify kind=blocked` 写清卡在哪 |
| 暂停待续 / 后台执行 | 待续用 `tick_pause` / `tick pause` 写恢复条件；执行器仍在后台时保留 running 并写真实执行证据，不虚构完成或用户问题 |
| 需要用户回答或操作 | `tick wait` 写成一眼能答的问题 |
| 收到用户回复或新指令 | 第一个工具调用就是更新 Tick：下一条标 `doing`；新任务先 `add` 再标 `doing`（只 `add` 不算更新）；不用做的 `skip` 写原因 |
| 全部做完或用户说不做了 | `tick finish` 写总结 |

结束回复前核对真实状态：完成才 finish，需要用户回答才 waiting，等待依赖用 blocked，待续用 pause；执行器确实在后台才保留 running。

子 agent：派出去时把本会话 ID 交给它，让它登记带 `parent_session_id`。自己是子 agent 时，不要 `wait` 问用户（要问的写进返回给主 agent 的结果），返回前 `tick finish` 自己的会话；否则它会一直挂在“等你”，用户回答后也不会消失。

大屏按 `doing` 展示当前流程：每条开始前先标 `doing`，完成立即 `done`；只有真实并行时才同时保留多个 `doing`。模块名保持简短稳定，追加清单时带上模块标题。主任务收尾前核对本次已返回的子任务也已 `finish`，取消项说明原因，不通过归档冒充完成。

业务分类使用模块，真实独立委派才建子会话，不为展示层级或绕过上限创建虚假子 Agent；父模块从条目自动汇总，不重复加“模块汇总任务”。API 按方法确定验收单位，同方法复测沿用稳定条目 ID，Run 链接放 evidence。done 是执行结束，result passed/failed/unknown/unverified 是验证结果，skipped 不算通过。失败仅阻断依赖分支，“等你”必须有具体用户问题。改名/移动模块用计划对象的现有 id 保留历史、结果与耗时。

Tick 返回遗漏提醒时，核对该稳定条目的真实执行证据，再确认 doing、标依赖 blocked、补 done/result 或说明原因 skipped。不要为消除提醒编进度、批量勾完，或把它转成没有具体问题的“等你”。

同一对话换目标仍复用原 `session_id`，不要省略或伪造 `conversation_id` 绕过去重。重新 `start` 会拿回原会话，不会改名。

调用方式：有 `tick_*` MCP 工具优先用；没有就用 `{{EXE}}`，它是窗口程序，PowerShell 里要接 `| Out-String` 才能拿到输出。
